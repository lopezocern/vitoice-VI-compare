# Krokiet 结果页重设计 · 设计说明 v0.1

> 目标：解决「看不出两组像不像」「178 组点不完」「不敢按删除」三个问题。
> 不改变引擎，只重构结果呈现与决策路径。
> 配套原型：`prototype.html`

---

## 1. 现状诊断

| 现象 | 根因 | 后果 |
|---|---|---|
| 只有文件名 + 一行分数 | 结果缺少视觉锚点 | 必须打开播放器才能判断 |
| 判断两个视频是否同源 | 没有对比手段，播放器来回切 | 单组耗时 1–2 分钟 |
| 178 组逐组点 | 没有批量策略，没有键盘流 | 全量清理要几小时 |

核心结论：**这不是"界面丑"的问题，是"决策链路太长"的问题。** 每一组要经过「读文件名 → 开播放器 → 记内容 → 切另一个 → 对比 → 回来点删除」，6 步。设计目标是压到 2 步。

---

## 2. 设计原则

1. **一眼可判**：每组的相似度、帧分布、文件差异，必须在一屏内可见，不点开也能筛掉 80%。
2. **同步即真相**：两个视频是否同源，取决于"同一时刻画面是否一致"。所有对比播放必须锁同一时间码。
3. **默认安全**：删除前自动预选、可撤销、进隔离区，让"误操作"的成本趋近于零，人才敢快。

---

## 3. 信息架构

```
┌ 顶栏：工具名 · 结果统计 · 过滤框 · 重新扫描 · 设置
├ 进度条（仅扫描中显示）
├ 左：工具导航（14 项，当前项高亮）
├ 中：分组列表 ── 组号 · 文件数 · 相似度 · 缩略图条 · 总大小
│                 排序：相似度 / 文件数 / 占用空间
└ 右：组详情 ── 同步胶片条 + 元数据 + 保留策略 + 决策
                   └ 全屏对比模式（模态）
底栏：选中统计 · 保留策略 · 隔离（删除）· 撤销 · 快捷键提示
```

**为什么是左右分栏而不是点击进详情页**：批量场景下，用户要在组与组之间快速跳跃。分栏保留了"列表上下文"，跳组不用返回。

---

## 4. 关键交互规格

### 4.1 同步胶片条（核心创新点）

- 每个文件一行，横向 8 帧（首帧起、按等分时长采样，与 pHash 采样点对齐）。
- 底部的**主时间轴**拖动时，所有行的当前帧高亮同步移动。
- 判断方式从"看视频"变成"看两排缩略图在同一个时间刻度上是否一致"——0.5 秒可判。
- 帧下方显示时间码（`00:03.2`），便于和原片核对。

### 4.2 相似度分级

| 区间 | 颜色 | 建议动作 |
|---|---|---|
| ≥ 95% | 绿 | 默认预选删除次要副本 |
| 85–95% | 黄 | 需要人工确认 |
| < 85% | 橙 | 默认不预选，避免误删 |

### 4.3 保留策略（一键）

`自动选最佳` 按以下优先级勾选保留项，其余标红：

1. 分辨率最高 → 2. 码率最高 → 3. 时长最长 → 4. 修改时间最早

策略可切换（例如"保留最早"用于素材归档场景）。

### 4.4 决策键（键盘流）

| 键 | 动作 |
|---|---|
| `J` / `K` | 下一组 / 上一组 |
| `D` | 标记当前组所有非保留文件 |
| `Space` | 播放 / 暂停（对比模式） |
| `←` `→` | 帧步进（1/8 段） |
| `Ctrl+Z` | 撤销上一次隔离 |
| `Enter` | 打开全屏对比 |

### 4.5 隔离区

- "删除"= 移动到 `_czkawka_trash\<批次时间戳>\`，并写 `manifest.json`（原路径、大小、哈希、批次）。
- 底栏常驻"撤销"；隔离区可整体回滚，也可批量清空。
- 绝不直接 `Delete`。

## 5. 视觉系统

### 5.1 色板

```
--bg        #0d0f13   页面底色
--panel     #14171d   面板
--panel-2   #1a1e26   悬浮/选中
--line      #262b36   分隔线
--text      #e6e9ef   主文本
--muted     #8b93a5   次要文本
--accent    #4c9aff   主操作
--ok        #34d399   保留
--warn      #fbbf24   待确认
--danger    #ff5f57   删除
```

对比度：主文本 on panel ≈ 12.8:1，muted on panel ≈ 5.4:1，均满足 WCAG AA。

### 5.2 字体与字号

- 字体：`Segoe UI, Microsoft YaHei, system-ui`
- 字号：11（时间码/辅助）、12（元数据）、13（正文）、14（列表主行）、16（面板标题）、20（组号）
- 数字统一 `font-variant-numeric: tabular-nums`，避免跳动。

### 5.3 间距与圆角

- 间距梯度：4 / 8 / 12 / 16 / 24
- 圆角：6（小控件）/ 8（面板）/ 10（卡片）
- 行高：列表行 44px，文件行 96px（含胶片条）

## 6. 状态清单

| 状态 | 呈现 |
|---|---|
| 扫描中 | 顶部细进度条 + 阶段文案 + 预计剩余；结果区保留上一次结果（灰化） |
| 无结果 | 空状态：图标 + "没有找到相似视频" + 建议（降低相似度 / 增大采样） |
| 单文件组 | 不展示（无决策价值） |
| 组内 ≥ 8 个 | 默认折叠到 5 行 + "展开全部" |
| 加载缩略图失败 | 占位块 + 文件名，不阻塞 |
| 错误 | 顶部红色横幅，可重试，不弹模态 |

## 7. 映射到 Slint 的实现要点

| 设计元素 | Slint 实现 | 注意 |
|---|---|---|
| 三栏布局 | `HorizontalLayout` + 固定宽度 rail(200px) / list(360px) / `VerticalLayout` 自适应 | 用 `min-width` 防挤压 |
| 分组列表 | `ListView` + 虚拟化 | 178 组必须虚拟化，否则卡 |
| 胶片条 | `HorizontalLayout` + `Image` × 8 | 帧图在扫描阶段就落盘缓存，UI 只读文件，避免运行时调 ffmpeg |
| 同步时间轴 | 单个 `Slider` 驱动 8 个 `Image` 的 `source` | 帧图切换用预生成的 8 张，避免高频重解码 |
| 对比播放 | 优先复用系统播放器外链；自绘播放成本高 | v1 建议"帧序列 + 外链播放"，不做内嵌播放器 |
| 键盘快捷键 | Slint `Keys` 处理器 | 与现有 focus 逻辑冲突，需统一焦点模型 |

**性能红线**：178 组 × 4 文件 × 8 帧 = 5696 张缩略图。必须懒加载 + 磁盘缓存，否则内存爆。

---

## 8. 验收标准

阶段 1 完成时应满足：

1. 单组判断时间从 60–120 秒降到 **10 秒以内**（3 组实测均值）。
2. 键盘完成 20 组的标记，**不超过 90 秒**。
3. 误删 0 次，且任意一次隔离可 **1 次点击回滚**。
4. 178 组列表滚动 **满帧**（60fps），内存 < 600 MB。

---

## 9. 不做的事（v1 范围外）

- 不改 14 个工具的信息架构，只做结果页（阶段 2/3 再谈）。
- 不做内嵌视频解码播放器，用帧序列 + 系统播放器。
- 不做云同步、不做 AI 语义相似度（后续可加）。
