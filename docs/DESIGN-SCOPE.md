# 扫描范围设计：包含目录 / 排除目录

> 现状：顶栏一个文本框，只能填一个目录，不能排除子目录，不能拖放，也不能记住上次。
> 目标：让「扫哪里、不扫哪里」变成一次可视、可校验、可复用的配置。

---

## 1. 为什么输入框不行

| 场景 | 输入框的表现 |
|---|---|
| 扫两个盘上的素材 | 只能填一个，得扫两次 |
| 不想扫 `# 123` 这个子目录 | 做不到，只能扫完手动过滤 |
| 不想扫 `_optimized` 输出目录 | 做不到，容易把优化产物当成新素材扫进来 |
| 路径输错一个字母 | 扫描时才发现，不报错就空跑 |
| 昨天刚扫过同一批 | 每次都要重新粘贴 |

最后一条尤其致命：**每天重复输入同一串长路径**，是这类工具最容易劝退的细节。

---

## 2. 模型

```
扫描集合 = ⋃(包含目录) − ⋃(排除目录)
```

- **包含目录**：0 到 n 个。为空时不能扫描。
- **排除目录**：0 到 n 个，优先级高于包含。
- 排除项支持两种形态：
  - **绝对路径**：`H:\NFZ\Celebrity\# 123`
  - **相对路径**：挂在某个包含目录下，显示为 `# 123（相对 H:\NFZ\Celebrity）`，移动根目录时不用改。

---

## 3. 交互规格

### 3.1 入口

顶栏右侧一个按钮：`📁 扫描范围 · 2 个目录`。点击展开浮层（popover），不跳页、不遮住结果。

结果为空时，主区域显示一个**大拖放区**：`把文件夹拖进来，或点击选择`。这是首次使用的主路径。

### 3.2 浮层结构

```
┌ 扫描范围 ─────────────────────────┐
│ 包含目录                           │
│  📁 H:\NFZ\Celebrity        ×      │
│  📁 G:\素材\2024            ×      │
│  ＋ 添加目录                       │
│                                    │
│ 排除目录（可选）                    │
│  🚫 # 123  相对 H:\NFZ\Celebrity × │
│  🚫 G:\素材\2024\_optimized      × │
│  ＋ 添加排除                       │
│                                    │
│ ⚠ 1 个排除目录不在任何包含目录内     │
│                                    │
│ 最近使用：NFZ ▾   G:\素材 ▾        │
│            [取消]      [开始扫描]   │
└────────────────────────────────────┘
```

### 3.3 规则

| 规则 | 行为 |
|---|---|
| 重复添加 | 忽略并提示「已添加过」 |
| 路径不存在 | 行标红，扫描按钮禁用，附「路径不存在」 |
| 排除项不在包含项下 | 行标黄，提示「将被忽略」，不阻断扫描 |
| 排除项的父级被移除 | 相对排除项自动转为绝对路径，避免失效 |
| 拖放 | 拖到「包含」区 = 包含；拖到「排除」区 = 排除 |
| 移除 | 行右侧 ×，无二次确认（可重新添加） |
| 持久化 | 记住最近 5 组配置，下次打开可一键恢复 |
| 扫描中 | 浮层仍可打开查看，但不可修改（避免竞态） |

### 3.4 路径显示

- 单行，**中间省略**：`H:\NFZ\Celeb…\DFaceNew`，保证盘符和末级目录都可见。
- 悬停显示完整路径的 tooltip。
- 相对路径优先显示相对形态，前面加一个小标记。

### 3.5 排除目录的「快捷入口」

扫描完成后，如果发现某个子目录特别吵（比如 `_optimized`），结果页顶栏出现一个提示条：

> 本次在 `_optimized` 下扫到 412 个文件，要排除它吗？ [加入排除]

一键加排除并重扫。这比让用户手动去浮层里翻目录高效得多。

---

## 4. 边界情况

| 情况 | 处理 |
|---|---|
| 根目录 `H:\` | 允许，但二次确认「将扫描整个磁盘」 |
| UNC 路径 `\\nas\share` | 允许，显示时保留 `\\` 前缀 |
| 超长路径（>260） | 显示截断，tooltip 完整，扫描前转 `\\?\` 前缀 |
| 符号链接 | 默认不跟随（walkdir `follow_links(false)`） |
| 包含与排除完全相同 | 允许，结果为 0 并提示 |
| 嵌套包含（父 + 子） | 允许，扫描时按父目录去重，避免重复遍历 |

## 5. 接口

```rust
struct ScanScope {
    includes: Vec<ScopeEntry>,
    excludes: Vec<ScopeEntry>,
}

struct ScopeEntry {
    path: String,
    relative_to: Option<String>,   // 相对路径时记录父包含项
}

// 命令
pick_folders() -> Vec<String>      // 调 tauri-plugin-dialog，目录多选
validate_scope(scope) -> Vec<Warning>  // 存在性 + 归属校验
save_scope(scope)                  // 持久化到 config
recent_scopes() -> Vec<ScanScope>
```

前端把 `ScanScope` 传给 `scan_start`，后端拼接遍历时先展开包含目录、再按排除前缀过滤。

---

## 6. 验收标准

1. 添加 3 个目录 + 2 个排除，**全程不碰键盘**（点选 + 拖放）。
2. 输入错误的路径，扫描前就能看到红色提示，不会空跑。
3. 关闭应用再打开，上次的范围还在。
4. 从结果页一键把「吵的子目录」加成排除，不需要重新找路径。
5. 扫描中修改范围被明确禁用，不会出现「改到一半开始扫」。
